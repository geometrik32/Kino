# Спецификация проекта Kino («Орловский кинопоказ»)

Живой документ с описанием архитектуры, реализованного функционала и требований ко всем платформам.

---

## 1. Назначение и концепция
Домашний стриминговый кинотеатр с каталогом фильмов и сериалов, потоковым воспроизведением прямо с торрентов и **синхронизацией прогресса между всеми устройствами** (веб, Telegram Mini App, компьютер, Android): та же раздача, та же серия, та же секунда.

---

## 2. Платформы и структура репозитория

Workspace Cargo (`Kino/Cargo.toml`) состоит из 6 крейтов:

| Крейт | Путь | Назначение |
|---|---|---|
| `kino-core` | `crates/core` | Общие типы API, каталога, прогресса, раздач, настроек пользователя и статуса буферизации (`StreamProgress`, `PlayInfo`, `ReleaseOption`, `UserPrefs` и др.). |
| `kino-server` | `crates/server` | HTTP API на `axum` + PostgreSQL (`sqlx`), авторизация через Telegram, проксирование TMDB/постеров, поиск раздач через Jackett, стриминг через TorrServer, перекодирование/субтитры через `ffmpeg`/`ffprobe`, предзагрузка через qBittorrent, фоновые джобы, раздача веб-статики. |
| `kino-bot` | `crates/bot` | Telegram-бот на `teloxide`: поиск, «Продолжить просмотр», списки, одноразовый вход на сайт (`/login`), приглашения (`/invite`), кнопка Mini App, уведомления о новых сериях. |
| `kino-ui` | `crates/ui` | Чистые UI-компоненты на Dioxus 0.7 (экраны, карточки, выбор раздачи, плеер, профиль, CSS-темы «Афиша» + «Бирюзовое кольцо»). Без сетевой логики и роутинга. |
| `kino-app` | `app` | Клиент на Dioxus 0.7 с 3 целевыми сборками: `web` (WASM + Telegram Mini App), `desktop` (Windows/macOS/Linux через `dioxus/desktop` WebView), `mobile` (Android через `dioxus/mobile` WebView + JNI в `app/src/platform/android.rs`). |
| `kino-preview` | `crates/preview` | Генерация статического HTML на демо-данных для визуальной проверки экранов без сборки WASM. |

---

## 3. Реализованный функционал

### 3.1. Авторизация и пользователи (`crates/server/src/session.rs`, `telegram_auth.rs`, `avatar.rs`, `api.rs`)
- Закрытый доступ только по приглашениям; администраторы задаются через `ADMIN_TELEGRAM_IDS`.
- Подписанные сессионные токены (`Authorization: Bearer <token>`).
- 3 способа входа:
  - Telegram Mini App (`POST /api/auth/webapp` по `initData`);
  - Telegram Login Widget на сайте (`POST /api/auth/widget`);
  - Одноразовая ссылка/код через Telegram-бота `/login` (`POST /api/auth/link`, `GET /api/auth/link/{token}`) — используется на сайте и в нативных приложениях.
- Аватарки пользователей (`crates/server/src/avatar.rs`): сервер загружает фото профиля из Telegram (через Bot API `getUserProfilePhotos`/`getFile` и резервно по `photo_url` через `TELEGRAM_PROXY`), кеширует в PostgreSQL и отдаёт через подписанный путь `GET /api/avatar/{token}`, возвращаемый в `Me.avatar_url` для шапки (`Shell`) и профиля (`ProfileView`).

### 3.2. Каталог и карточка тайтла (`crates/server/src/catalog/`, `crates/ui/src/lib.rs`)
- Интеграция с TMDB на русском языке (с поддержкой прокси `TMDB_PROXY`, проксированием изображений через `GET /api/img/{size}/{file}`, устойчивым к `е`/`ё` поиском с нормализацией и резервными запросами, а также поддержкой года в конце поискового запроса вида «Название 1997»); без `TMDB_API_KEY` работает встроенный демо-каталог (также с нормализацией `е`/`ё` и фильтрацией по году из запроса).
- Главная страница (`HomeView`, `ShelfView` в `crates/ui/src/lib.rs`, `app/src/main.rs`, `crates/server/src/catalog/personalize.rs`):
  - блок «Продолжить просмотр» всегда первый сверху и загружается независимо от каталожных подборок (с предложением бросить давно не просмотренные тайтлы);
  - полоса категорий сверху (`Для вас`, `Пересматривай любимое`, `Сериалы`, `Фильмы`, `Новинки`, `Аниме и мультфильмы`, жанры, `Русское`) и расширенный набор до 24 подборок TMDB: на старте загружаются только верхние 5 подборок, остальные скрыты лёгкими заглушками и подгружаются порциями по мере прокрутки (`GET /api/catalog/home/shelves`) или при выборе категории;
  - персонализация на сервере по истории, оценкам и статусам пользователя: динамические полки «Потому что вы смотрели «…»», «Смотрят и советуют участники» (`peers`) и «Пересматривай любимое» (`rewatch`, завершённые с оценкой ≥4★), адаптивное ранжирование жанров и формата, полное исключение просмотренного, оценённого, ожидаемого и брошенного из обычных подборок;
  - на всех постерах собственная оценка пользователя (1–5★ или дробная расчётная) отображается золотым цветом вместо оценки TMDB, показываются статус просмотра и отметка активности других участников;
  - горизонтальные ленты (`ScrollRow`) с кнопками пролистывания `‹`/`›` на десктопе, свайпами на сенсорных устройствах, автоподгрузкой следующих страниц (`GET /api/catalog/shelf/{id}?page=N`) и кнопкой «Все» (в заголовке и в конце ленты) для просмотра подборки сеткой в `ShelfView`.
- Поиск фильмов и сериалов (`SearchView`) и раздел «Мои» (`crates/ui/src/account.rs`): вкладки «Мои списки», «Участники» (`/api/users`, `/api/users/{id}/titles` с живым статусом просмотра и библиотеками участников) и «Календарь» (`/api/calendar` с датами новых серий и ожидаемых премьер).
- Карточка тайтла (`TitleView`, `TitleExtrasView`): описание, рейтинг, выбор статуса (`Смотрю`, `Жду следующей серии` авто для продолжающихся сериалов, `Просмотрено`, `Хочу посмотреть`, `Жду` для невышедших фильмов, `Брошено`), иерархические оценки 1–5★ отдельно для сериала, каждого сезона (`PUT /api/title/tv/{id}/season/{s}/rating`) и каждой серии (`PUT /api/title/tv/{id}/season/{s}/episode/{e}/rating`) с порогом 80% расчёта снизу вверх, пропорциональным заполнением звёзд, всплывающими описаниями градации 1–5 и всплывающим меню альтернативного запуска («Все серии подряд», «Только любимые (5★)», «Хорошие и любимые (4–5★)»), строка участников, сезоны и серии с отметками просмотра (`POST /api/marks`), актёрский состав и фильмография (`PersonView`), рекомендации и похожие.
- Навигация, шапка и кэширование состояния (`app/src/main.rs`, `app/src/telegram/web.rs`, `crates/ui/src/lib.rs`, `crates/ui/src/account.rs`):
  - В шапке `Shell` на широких экранах строка поиска (`Ctrl+K` / `Cmd+K`) размещена по центру (`.top-center`) между логотипом с вкладками слева и профилем/индикатором загрузок справа; на мобильных экранах поиск открывается отдельной вкладкой нижней панели.
  - Карточки тайтлов (`PosterCard`), ссылки на карточки в `ContinueCard`, истории, предзагрузках, календаре и активности участников, а также карточки актёров и ссылки подборок «Все» используют нативные `<a href="/?open=...">` (и `/?person=`, `/?shelf=`): обычный левый клик выполняет быстрый SPA-переход, а средняя кнопка мыши и `Ctrl`/`Cmd`+клик на ПК открывают страницу в новой вкладке.
  - В веб-версии (вне Telegram) переходы по экранам (`Title`, `Person`, `Shelf`, вкладки, `Search`) и оверлеям (`ReleasePicker`, `Player`, уведомление предзагрузки) синхронизируются с историей браузера (`pushState` / `popstate` с `history.scrollRestoration = 'manual'`), а при открытии тайтла адресная строка обновляется на `/?open=<kind>_<id>`.
  - Клиентский кэш `AppCache` (плюс `sessionStorage`-снимок главной на время переходов) сохраняет загруженные подборки, догруженные страницы, фильтры, выбранный сезон, горизонтальную прокрутку лент (`ScrollRow` и полоса категорий) и вертикальную позицию `TrailEntry`: при возврате «Назад» экран восстанавливается на том же месте без сброса списков, а «Продолжить просмотр», оценки/статусы и списки «Мои»/профиля актуализируются в фоне.
  - В окне выбора раздачи (`ReleasePicker`) есть кнопка закрытия `✕`.
  - При запуске плеера напрямую из «Продолжить просмотр» или ссылки `&play=1` кнопка «Назад» браузера / системный жест возвращают на предыдущий экран (`Home`) с восстановлением прокрутки, а нажатие на название фильма в шапке плеера открывает карточку тайтла.

### 3.3. Поиск и выбор раздач (`crates/server/src/torrent/`, `crates/ui/src/releases.rs`)
- Поиск по трекерам через Jackett (Torznab) и опциональные дополнительные Torznab-источники (`EXTRA_TORZNAB_URLS`, например публичное зеркало JacRed `https://jac-red.ru`) с параллельным опросом, слиянием и дедупликацией результатов (приоритет основного Jackett, нормализация имён трекеров вроде `rutracker, ...` → `RuTracker`, устойчивость к таймауту/сбою отдельного источника), кешированием (`search_cache.rs`) и фоновой предзагрузкой списка при открытии карточки (`prefetch_releases`): для фильмов и односезонных сериалов/мини-сериалов запрос дополняется годом (для односезонных с резервным поиском без года при пустой выдаче), для многосезонных сериалов выполняется поиск по названию с резервным запросом по году старта.
- Строгая фильтрация результатов трекеров (`torrent/mod.rs`, `torznab.rs`): учёт Torznab-категорий, проверка года релиза/диапазонов лет сезонов (для фильмов, односезонных и многосезонных сериалов), разделение фильмов и сериалов (маркеры сезонов/серий), сегментное сопоставление русского и оригинального названий (игнорирование названий серий после `SxxExx`, отсечение чужих локализованных фильмов с противоречащим латинским оригиналом).
- Парсинг параметров из названия раздачи (`title.rs`): качество (`2160p`/`1080p`/`720p`/`SD`), `HDR`, `Dolby Vision`, кодек (`H.264`, `HEVC`, `AV1`), студия/тип озвучки, язык (учитывая `RUS`/кириллицу и исключая пометки только-субтитров и ложную одиночную `D` в латинице), наличие субтитров, сезон, год (с приоритетом года в скобках и поддержкой диапазонов `2005-2020`), битрейт (или приблизительный расчёт по размеру и длительности).
- Фильтры и сортировка раздач; сохранение фильтров по умолчанию в профиле (`UserPrefs`), при этом выбранный язык озвучки сохраняется строго и не сбрасывается при отсутствии совпадений по второстепенным фильтрам (пока пользователь сам не нажмёт «Показать на всех языках»).
- Запоминание выбранной раздачи отдельно по фильму/сезону/серии и бакету качества (`2160p`/`1080p`/`720p`/`SD`), автоподбор качества по устройству (`POST /api/releases/{kind}/{id}/resolve`: телефон `720p`/`SD`, ПК `1080p` с переопределением в профиле) и автоматическое перенятие раздачи других участников при совпадении целевого качества; быстрая смена качества через вкладку «Качество» в поповере «Звук и субтитры» плеера с сохранением позиции (`PUT /api/release-quality`).
- Теги совместимости в списке раздач:
  - `играет сразу` — если в названии `H.264`, без `HDR` и не `2160p`;
  - `перекодируется` — если указан `HEVC`/`AV1` или `HDR` (для нативного плеера Android при `native_player = true` фильтры `Играет сразу`/`Без перекодирования` и тег `перекодируется` скрываются, т.к. поток воспроизводится напрямую).

### 3.4. Воспроизведение, дорожки и стриминг (`crates/server/src/play.rs`, `ffmpeg.rs`, `app/src/player.rs`, `crates/ui/src/player.rs`)
- Выбор нужного файла внутри раздачи (`files.rs`), в том числе в многосерийных паках и сезонах.
- Поддержка предзагрузки на диск сервера через qBittorrent («Скачать заранее» в списке раздач с отображением статуса/прогресса, двухшаговой отменой и без закрытия окна, индикатор активных загрузок на карточке и единый список качеств во вкладке «Качество» в плеере с кнопкой скачивания на активной раздаче, отменой загружаемых и бейджами озвучки/размера/сидов/трекера) и автоудаления через `PRELOAD_KEEP_DAYS` после просмотра; сервер (повторные запросы и `409 Conflict` qBittorrent обрабатываются идемпотентно со схлопыванием `u...`-ключей в единый info-хэш) в `jobs::sync_preloads` каждые 5 с рассылает WebSocket-событие `PreloadReady`, и в плеере без прерывания просмотра появляется плашка в формате «Следующей серии» с деталями завершившейся раздачи текущего фильма/сезона и предложением переключиться на файл с диска с отмоткой на 1 с назад.
- Стриминг через TorrServer (`ConnectionsLimit = 100` для быстрого набора пиров, с разделением подключённых сидов и общего числа пиров в статусе подключения) или с диска через `ServeFile` для предзагруженных файлов по подписанной ссылке `/api/stream/{token}` на 12 часов; перед добавлением проверяется активность торрента в TorrServer, все запросы к TorrServer, `ffprobe`/`ffmpeg` (HTTP `-rw_timeout`), старту потока и ожиданию в плеере защищены таймаутами, а зависшие нулевые раздачи без раздающих при неудачном старте, отмене или таймауте предзагрузки автоматически выгружаются из TorrServer (`action: "drop"`).
- **SSD-кеш паузы (`crates/server/src/torrent/pause_cache.rs`, `fmp4.rs`):** во время обычного просмотра буфер не пишется на диск; через ~10 с паузы, 8 с после закрытия потока или сразу при выходе из плеера (`POST /api/sync/leave`) сервер сохраняет на SSD метаданные разбора (`Probe`), заголовок/хвост файла (`8 МБ` / `6 МБ`), все считанные во время поиска ключевых кадров метаданные контейнера (`meta_*.bin`), ~42 с сырого окна вокруг позиции паузы (`32–128 МБ`, от `10 с` и до `90%`), а для транскодируемых потоков браузера — ещё и **готовый перекодированный fMP4-префикс (`ready.mp4`, ~22–30 с под активную звуковую дорожку)**. При возврате к фильму на той же позиции/дорожке `ready.mp4` отдаётся сразу с SSD без ожидания `ffmpeg` и торрент-сети, а сервер параллельно запускает продолжение `ffmpeg` с точной стыковкой `moof`/`tfdt` (сверкой `stsd`/`timescale` и IDR-хэша при `-c:v copy`, с автоматическим самовосстановлением клиента при редком несовпадении); при смене дорожки или сдвиге позиции старт идёт с сырых SSD-срезов. Кроме того, прокси к TorrServer прозрачно переподключается по `Range` при сбросе простоя. Бюджет на SSD — до `5 ГБ` (вытеснение по давности) и срок жизни `72 часа`, `ffprobe` дополнительно кешируется в RAM до 12 часов.
- Отображение прогресса подключения/буферизации торрента (`GET /api/play/progress/{release}`) и статусной карточки `.p-wait` / `.connect` на полупрозрачной тёмно-серой подложке на всех этапах ожидания («Подключаемся к раздаче…», предзагрузка начала, запуск перекодирования/потока, буферизация).
- Анализ файла через `ffprobe`: длительность, контейнер, видеокодек, список аудиодорожек и текстовых субтитров.
- Извлечение текстовых субтитров в WebVTT (`GET /api/stream/{token}/sub/{n}.vtt`) работает для предзагруженных на диск сервера релизов (`preloaded`); для живого стрима через TorrServer встроенные субтитры отключены с подсказкой в плеере, чтобы чтение всего MKV до конца файла не блокировало `<video>` и не перегружало кеш TorrServer.
- **Текущая логика перекодирования / прямой отдачи:**
  - Прямая отдача (с HTTP `Range`) используется, если клиент передал `PlayRequest.native = true` (нативное Android-приложение), либо если `probe.browser_ok()` истинно (`mov,mp4` + видео `h264`/`vp9`/`av1` + звук по умолчанию `aac`/`mp3`/`opus`/`vorbis`) **и** выбрана аудиодорожка по умолчанию.
  - Во всех остальных случаях браузера/Mini App (`.mkv`, `HEVC`, `AC3`/`DTS`, выбор другой аудиодорожки или ошибка декодера с откатом в `force_transcode`) сервер запускает `ffmpeg` на лету (лимит по умолчанию `MAX_TRANSCODES = 6`, таймаут простоя на паузе — 9 минут на сервере и 8 минут на клиенте до принудительного переподключения), отдавая фрагментированный MP4:
    - при видео `H.264` используется `-c:v copy` (перекодируется только аудио в `AAC` stereo 192k, а при `-ss > 0` добавляется `-noaccurate_seek` для сохранения A/V-синхронизации);
    - при других видеокодеках видео перекодируется в `H.264` (`libx264`, либо аппаратно `h264_qsv` / `h264_vaapi` при `TRANSCODE_HWACCEL`).
- **Нативный плеер Android (`app/android/MainActivity.kt`, `app/android/proguard-kino.pro`, `app/android/res/`, `app/src/platform/android.rs`, `app/src/platform/video.rs`, `app/Dioxus.toml`):**
  - Под прозрачным `WebView` (`with_background_color((0, 0, 0, 0))`, `.player.native-video` / `html.native-video`) размещён `AndroidX Media3 ExoPlayer` (`1.9.0`) + программный аудиодекодер `org.jellyfin.media3:media3-ffmpeg-decoder` (`1.9.0+1`) в режиме `EXTENSION_RENDERER_MODE_ON`: аппаратное декодирование видео (`MediaCodec` для H.264/HEVC/AV1/HDR) и декодирование `AC3`/`EAC3`/`DTS`/`TrueHD`/FLAC через FFmpeg, вывод через `TextureView` + `SubtitleView`. Если видеодорожка не поддерживается декодерами устройства (например, `mpeg2video` в DVDRemux) или за 5 секунд не отрисован первый кадр, `ExoPlayer` сигнализирует ошибку и клиент автоматически переключается на серверный `ffmpeg`-поток (`force_transcode`).
  - Управление системными отступами вынесено в `OnApplyWindowInsetsListener`: обычные экраны получают padding под системные бары и вырезы на уровне `View`, а в плеере скрытая навигационная панель не сдвигает интерфейс (`WindowInsetsCompat.CONSUMED`, в CSS передаётся только `displayCutout`). Приложение собирается под именем «Орловский кинопоказ» и со встроенными иконками из `app/android/res/` (`Adaptive Icon` + PNG).
  - Управление, меню аудиодорожек и встроенных субтитров, масштабирование кадра («По ширине» / «По высоте» в `AspectRatioFrameLayout` с `SubtitleView` внутри `playerContainer`), прогресс каждые 10 с, скорость, перемотка, удержание экрана (`keepScreenOn`), переход к следующей серии и Watch Together-синхронизация сохраняются поверх единого UI `PlayerView`; смена аудиодорожки/субтитров происходит внутри `ExoPlayer` без перезапуска потока и без `ffmpeg` на сервере.
- Плеер в клиенте (`app/src/player.rs`, `app/src/sync.rs`, `crates/server/src/sync.rs`, `crates/ui/src/player.rs`): автоскрытие интерфейса управления (включая верхнюю/нижнюю панель, центральную кнопку `▶` на паузе и курсор мыши на десктопе) через `CONTROLS_MS = 3.5 с` бездействия как во время воспроизведения, так и при паузе с показом по движению мыши, нажатию контролов или тапу; переключение масштаба картинки между 2 пропорциональными режимами («По ширине» и «По высоте» экрана, со стартом без обрезки до ручного выбора и запоминанием в БД `title_state.video_scale` через `PUT /api/title/{kind}/{tmdb_id}/scale` и локальным кешем в `localStorage`); сохранение позиции каждые 10 секунд с именем устройства, переход к следующей серии (с фоновым подбором раздачи и прогревом начала следующей серии в TorrServer + `ffprobe` при появлении плашки следующей серии за 40 с до конца, с защитой буфера текущей серии и сбросом при смене дорожки/качества), скорость воспроизведения, двойной тап ±10 с, выбор дорожек/субтитров (запоминается для тайтла), полноэкранный режим (`navigationUI: 'hide'`, повтор по тапу, `WindowInsetsController` и чёрные бары Telegram в плеере), поворот в ландшафт на Android, чистая пауза с кнопкой `▶` при запрете автовоспроизведения со звуком (без принудительного отключения звука) и **живая синхронизация просмотра между устройствами одного аккаунта** (`POST /api/sync/join`, `POST /api/sync/leave`, `GET /api/sync/ws`: воспроизведение/пауза, таймкод с калибровкой часов и автокоррекцией рассинхрона, скорость, перемотка, смена серии/раздачи/дорожки, взаимное ожидание буферизации, защита `watch_progress` от устаревших перезаписей, единый владелец звука комнаты `sound_client_id` с автоматическим глушением остальных устройств и переключением вывода кнопками «Звук здесь» / «Звук там» в поповере синхронизации, а также REC-индикатор со списком устройств при 2+ активных подключениях).

### 3.5. Профиль, история и Telegram-бот
- Профиль (`crates/ui/src/account.rs`): тема оформления (`Тёмная`, `Светлая`, `Как в Telegram`), настройки качества по умолчанию для ПК и телефона, фильтров раздач и языка озвучки (без предварительного выбора субтитров), список предзагрузок, история просмотров по устройствам.
- Telegram-бот (`crates/bot`): команды `/start`, `/search`, `/random`, `/continue`, `/my`, `/trending`, `/login`, `/help`, `/invite`; синяя кнопка Mini App «Кино» слева от поля ввода и постоянная клавиатура быстрых команд без её дублирования в личных чатах (плюс inline-кнопки команд в `/help`); карточки фильмов в поиске с постером, описанием и кнопкой открытия в Mini App (плюс кнопки дозагрузки карточек остальных результатов); настраиваемая ежедневная и ручная отправка дайджеста «Сегодня в тренде» одним альбомным сообщением с кликабельными ссылками (`sendMediaGroup`); интерактивный подбор случайного фильма (`/random`: полностью случайный или по жанру, примерной длительности, рейтингу и проценту отклонения); кнопки из `/continue` открывают Mini App с автозапуском проигрывателя (`/?open=<kind>_<id>&play=1`); уведомления о выходе новых серий и релизов (`crates/server/src/jobs.rs`).

### 3.6. База данных и деплой
- PostgreSQL (миграции `crates/server/migrations/0001..0010`): таблицы `users`, `invites`, `watch_progress`, `watchlist`, `release_choice`, `device_quality_choice`, `title_state`, `season_rating`, `episode_rating`, `watch_history`, `user_prefs`, `preload`, `torrent_source`, `login_link`, `media_cache`, `search_cache`.
- Docker / TrueNAS стек (`deploy/compose.yaml`, `Dockerfile`): `kino-db`, `kino-server` (с пробросом `/dev/dri` для VA-API/QSV, кешем картинок на M.2 SSD, `MAX_TRANSCODES = 6`, лимит `1280m`), `kino-bot`, `torrserver` (потоковый буфер в RAM `UseDisk: false`, `GOMEMLIMIT: 960MiB`, лимит `1280m`, `TorrentDisconnectTimeout: 90`), `jackett` (автосон через `sablier`), `qbittorrent` за Traefik.
- CI (`.github/workflows/ci.yml`, `.github/workflows/android.yml`): `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `cargo clippy -p kino-app --target wasm32-unknown-unknown --locked -- -D warnings`, сборка Docker-образа; отдельный workflow `.github/workflows/android.yml` для сборки `arm64` APK (`dx bundle --package kino-app --platform android --target aarch64-linux-android --release --package-types apk`).

## 4. Требования к целевым платформам

| Платформа | Клиент | Требования к воспроизведению | Текущий статус |
|---|---|---|---|
| **Web / Telegram Mini App** | `kino-app` (`web`) | Браузерный `<video>`, серверная адаптация через `ffmpeg` для несовместимых форматов. | Работает. |
| **Desktop (Windows / macOS / Linux)** | `kino-app` (`desktop`) | Должен воспроизводить сложные кодеки и контейнеры (`HEVC`, `AV1`, `HDR`, `.mkv`, `AC3`/`DTS`) **напрямую на клиенте без перекодирования на сервере**, с переключением аудиодорожек и субтитров. | **Отложено по решению владельца** (сейчас приоритет на Android; общий серверный протокол `PlayRequest.native` готов, см. `ISSUE-001` в `docs/ISSUES.md`). |
| **Android** | `kino-app` (`mobile`) | Должен воспроизводить сложные кодеки и контейнеры (`HEVC`, `HDR`, `.mkv`, `AC3`/`DTS`) **напрямую на клиенте без перекодирования на сервере**, с сохранением внутриприложенческого UX (прогресс, дорожки, следующая серия). | **Реализовано в коде (`ExoPlayer` + `Jellyfin FFmpeg`)**; ожидает сборки APK в GitHub Actions и проверки на реальном Android-устройстве (см. `ISSUE-001`). |
