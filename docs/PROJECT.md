# Спецификация проекта Kino («Орловский кинопоказ»)

Живой документ с описанием архитектуры, реализованного функционала и требований ко всем платформам.

---

## 1. Назначение и концепция
Домашний стриминговый кинотеатр с каталогом фильмов и сериалов, потоковым воспроизведением прямо с торрентов и **синхронизацией прогресса между всеми устройствами** (веб, Telegram Mini App, компьютер, Android): та же раздача, та же серия, та же секунда.

---

## 2. Платформы и структура репозитория

Workspace Cargo (`Kino/Cargo.toml`) состоит из 6 крейтов:

| Крейт | Путь | Назначение |
|---|---|---|
| `kino-core` | `crates/core` | Общие типы API, каталога, прогресса, раздач, настроек пользователя и статуса буферизации (`StreamProgress`, `PlayInfo`, `ReleaseOption`, `UserPrefs` и др.). |
| `kino-server` | `crates/server` | HTTP API на `axum` + PostgreSQL (`sqlx`), авторизация через Telegram, проксирование TMDB/постеров, поиск раздач через Jackett, стриминг через TorrServer, перекодирование/субтитры через `ffmpeg`/`ffprobe`, предзагрузка через qBittorrent, фоновые джобы, раздача веб-статики. |
| `kino-bot` | `crates/bot` | Telegram-бот на `teloxide`: поиск, «Продолжить просмотр», списки, одноразовый вход на сайт (`/login`), приглашения (`/invite`), кнопка Mini App, уведомления о новых сериях. |
| `kino-ui` | `crates/ui` | Чистые UI-компоненты на Dioxus 0.7 (экраны, карточки, выбор раздачи, плеер, профиль, CSS-темы «Афиша» + «Бирюзовое кольцо»). Без сетевой логики и роутинга. |
| `kino-app` | `app` | Клиент на Dioxus 0.7 с 3 целевыми сборками: `web` (WASM + Telegram Mini App), `desktop` (Windows/macOS/Linux через `dioxus/desktop` WebView), `mobile` (Android через `dioxus/mobile` WebView + JNI в `app/src/platform/android.rs`). |
| `kino-preview` | `crates/preview` | Генерация статического HTML на демо-данных для визуальной проверки экранов без сборки WASM. |

## 3. Реализованный функционал

### 3.1. Авторизация и пользователи (`crates/server/src/session.rs`, `telegram_auth.rs`, `api.rs`)
- Закрытый доступ только по приглашениям; администраторы задаются через `ADMIN_TELEGRAM_IDS`.
- Подписанные сессионные токены (`Authorization: Bearer <token>`).
- 3 способа входа:
  - Telegram Mini App (`POST /api/auth/webapp` по `initData`);
  - Telegram Login Widget на сайте (`POST /api/auth/widget`);
  - Одноразовая ссылка/код через Telegram-бота `/login` (`POST /api/auth/link`, `GET /api/auth/link/{token}`) — используется на сайте и в нативных приложениях.

### 3.2. Каталог и карточка тайтла (`crates/server/src/catalog/`, `crates/ui/src/lib.rs`)
- Интеграция с TMDB на русском языке (с поддержкой прокси `TMDB_PROXY`, проксированием изображений через `GET /api/img/{size}/{file}` и устойчивым к `е`/`ё` поиском с нормализацией и резервными запросами); без `TMDB_API_KEY` работает встроенный демо-каталог (также с нормализацией `е`/`ё`).
- Главная страница (`HomeView`): блок «Продолжить просмотр» (с предложением бросить давно не просмотренные тайтлы), подборки.
- Поиск фильмов и сериалов (`SearchView`).
- Карточка тайтла (`TitleView`, `TitleExtrasView`): описание, рейтинг, выбор статуса (`Смотрю`, `Просмотрено`, `Хочу посмотреть`, `Брошено`), оценка 1–5 звёзд, сезоны и серии с отметками просмотра (`POST /api/marks`), актёрский состав и фильмография (`PersonView`), рекомендации и похожие.

### 3.3. Поиск и выбор раздач (`crates/server/src/torrent/`, `crates/ui/src/releases.rs`)
- Поиск по трекерам через Jackett (Torznab) с кешированием (`search_cache.rs`) и фоновой предзагрузкой списка при открытии карточки (`prefetch_releases`).
- Парсинг параметров из названия раздачи (`title.rs`): качество (`2160p`/`1080p`/`720p`/`SD`), `HDR`, `Dolby Vision`, кодек (`H.264`, `HEVC`, `AV1`), студия/тип озвучки, язык, наличие субтитров, сезон, год, битрейт (или приблизительный расчёт по размеру и длительности).
- Фильтры и сортировка раздач; сохранение фильтров по умолчанию в профиле (`UserPrefs`).
- Запоминание выбранной раздачи для фильма или конкретного сезона сериала (`release_choice`).
- Теги совместимости в списке раздач:
  - `играет сразу` — если в названии `H.264`, без `HDR` и не `2160p`;
  - `перекодируется` — если указан `HEVC`/`AV1` или `HDR`.

### 3.4. Воспроизведение, дорожки и стриминг (`crates/server/src/play.rs`, `ffmpeg.rs`, `app/src/player.rs`, `crates/ui/src/player.rs`)
- Выбор нужного файла внутри раздачи (`files.rs`), в том числе в многосерийных паках и сезонах.
- Поддержка предзагрузки на диск сервера через qBittorrent («Скачать заранее» для раздач с малым числом сидов) и автоудаления через `PRELOAD_KEEP_DAYS` после просмотра.
- Стриминг через TorrServer (или с диска через `ServeFile` для предзагруженных файлов) по подписанной ссылке `/api/stream/{token}` на 12 часов; перед добавлением проверяется активность торрента в TorrServer, все запросы к TorrServer, `ffprobe`/`ffmpeg` (HTTP `-rw_timeout`), старту потока и ожиданию в плеере защищены таймаутами, чтобы при отсутствии сидов или сбое TorrServer пользователь получал понятную ошибку вместо бесконечного «Ищем раздающих…».
- Отображение прогресса подключения/буферизации торрента (`GET /api/play/progress/{release}`).
- Анализ файла через `ffprobe`: длительность, контейнер, видеокодек, список аудиодорожек и текстовых субтитров.
- Извлечение текстовых субтитров в WebVTT (`GET /api/stream/{token}/sub/{n}.vtt`).
- **Текущая логика перекодирования / прямой отдачи:**
  - Прямая отдача (с HTTP `Range`) используется, только если `probe.browser_ok()` истинно (`mov,mp4` + видео `h264`/`vp9`/`av1` + звук по умолчанию `aac`/`mp3`/`opus`/`vorbis`) **и** выбрана аудиодорожка по умолчанию.
  - Во всех остальных случаях (`.mkv`, `HEVC`, `AC3`/`DTS`, выбор другой аудиодорожки или ошибка `<video>` с откатом в `force_transcode`) сервер запускает `ffmpeg` на лету (ограничение — не более `MAX_TRANSCODES = 2` одновременных потоков), отдавая фрагментированный MP4:
    - при видео `H.264` используется `-c:v copy` (перекодируется только аудио в `AAC` stereo 192k);
    - при других видеокодеках видео перекодируется в `H.264` (`libx264`, либо аппаратно `h264_qsv` / `h264_vaapi` при `TRANSCODE_HWACCEL`).
- Плеер в клиенте (`app/src/player.rs`): сохранение позиции каждые 10 секунд с именем устройства, переход к следующей серии, скорость воспроизведения, двойной тап ±10 с, выбор дорожек/субтитров (запоминается для тайтла), полноэкранный режим и поворот в ландшафт на Android.

### 3.5. Профиль, история и Telegram-бот
- Профиль (`crates/ui/src/account.rs`): тема оформления (`Тёмная`, `Светлая`, `Как в Telegram`), настройки раздач по умолчанию, выбор языка субтитров, список предзагрузок, история просмотров по устройствам.
- Telegram-бот (`crates/bot`): команды `/start`, `/search`, `/continue`, `/my`, `/login`, `/help`, `/invite`; постоянная клавиатура быстрых команд в личных чатах и inline-кнопки команд в `/help`; карточки фильмов в поиске с постером, описанием и кнопкой открытия в Mini App (плюс кнопки дозагрузки карточек остальных результатов); уведомления о выходе новых серий отслеживаемых сериалов (`crates/server/src/jobs.rs`).

### 3.6. База данных и деплой
- PostgreSQL (миграции `crates/server/migrations/0001..0006`): таблицы `users`, `invites`, `watch_progress`, `watchlist`, `release_choice`, `title_state`, `watch_history`, `user_prefs`, `preload`, `torrent_source`, `login_link`.
- Docker / TrueNAS стек (`deploy/compose.yaml`, `Dockerfile`): `kino-db`, `kino-server` (с пробросом `/dev/dri` для VA-API/QSV), `kino-bot`, `torrserver`, `jackett`, `qbittorrent` за Traefik.
- CI (`.github/workflows/ci.yml`): `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `cargo clippy -p kino-app --target wasm32-unknown-unknown --locked -- -D warnings`, сборка Docker-образа.

## 4. Требования к целевым платформам

| Платформа | Клиент | Требования к воспроизведению | Текущий статус |
|---|---|---|---|
| **Web / Telegram Mini App** | `kino-app` (`web`) | Браузерный `<video>`, серверная адаптация через `ffmpeg` для несовместимых форматов. | Работает. |
| **Desktop (Windows / macOS / Linux)** | `kino-app` (`desktop`) | Должен воспроизводить сложные кодеки и контейнеры (`HEVC`, `AV1`, `HDR`, `.mkv`, `AC3`/`DTS`) **напрямую на клиенте без перекодирования на сервере**, с переключением аудиодорожек и субтитров. | **Не реализовано** (сейчас играет через WebView `<video>`, см. `ISSUE-001` в `docs/ISSUES.md`). |
| **Android** | `kino-app` (`mobile`) | Должен воспроизводить сложные кодеки и контейнеры (`HEVC`, `HDR`, `.mkv`, `AC3`/`DTS`) **напрямую на клиенте без перекодирования на сервере**, с сохранением внутриприложенческого UX (прогресс, дорожки, следующая серия). | **Не реализовано** (сейчас играет через системный WebView `<video>`, см. `ISSUE-001` в `docs/ISSUES.md`). |
